# Completion checklist

## Content and navigation

- All promised areas exist and use current, attributable data.
- No obsolete project or duplicate report system remains.
- Every interactive object has an accessible label and a real action.
- A guide accurately lists the available interactions.

## Persistence

- Autosave shows its true state.
- Reload recovery is tested.
- Concurrent edits produce a visible conflict rather than data loss.
- Imports validate provenance, completeness, and date.
- Backups or transaction history can recover prior content.

## Experience

- Scene motion is calm, purposeful, and optional.
- Day/night themes preserve contrast.
- Mobile touch targets and reading surfaces are usable.
- Rewards follow real completed tasks without replacing project records.
- Mini-games are optional and cannot corrupt work data.

## PWA and cloud

- Manifest, icon, service worker, and offline shell are valid.
- Private APIs are excluded from static caches.
- Hosted data is isolated by authenticated user ID.
- The phone works while the original computer is off.
- Deployment access is private unless the user explicitly chose otherwise.

## Publication hygiene

- Search for personal names, emails, IDs, dates tied to private work, local paths, tokens, and project titles.
- Confirm no data files, backups, screenshots, or generated archives contain private records.
- Validate the skill package and inspect the final repository tree.
